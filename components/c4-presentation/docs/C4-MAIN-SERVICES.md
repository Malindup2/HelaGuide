## 1. The HTTP 409 on PATCH /workspace/guidance/profile-context/{session}
- **Root cause:** the editor sent the identity session's own `revision` as `expected_identity_revision`. The backend checks the settings revision, which is the session revision plus a native settings revision that every saved edit increments. The first save worked because the native part was 0; after it the two numbers differed, so every later save looked like a stale write.
- **Fix (backend check untouched):** the editor reads the current revision from `GET /context` immediately before saving, refreshes the context after saving, and shows a plain "changed in another window, reloaded" message on a genuine 409.
- **Proof:** `service/tests/test_profile_context_revision.py` reproduces the old behaviour (second save 409), keeps genuinely stale writes refused, and runs repeated 1 to 4 changes on three profiles with the real PP1 policy. The saved familiarity appears in the encoder's selected features, survives a restart, and a change from 4 back to 1 changes the features. A frontend test checks the revision sent on three consecutive saves. In the running app five consecutive saves (4, 1, 4, 2, 4) all returned 200; after a page reload familiarity was still 4 and fresh guidance reported it.

## 3. Conflicts and gaps found
- Birth: the older GIC page lists Rs. 100 and Rs. 200; the current RGD pages list Rs. 120 and Rs. 250 (used). The separate eBMD online route is not mixed in.
- NIC: the affidavit age threshold is 40 in the amendment section and 50 in the first-issue section, and the paragraph has a stray "(delete)" marker; stated as 40 and flagged in Sources. The one-day service is mentioned as a separate in-person option without its fee or hours.
- TIN: the 2026 guideline gives no fee and no counter hours; the older "nil" fee is shown as a Charge LKR 0 card annotated "older GIC description". Hours and the 20-minute service time are not used. The 2020-dated registration page describes in-person and postal channels, which the 2026 guideline does not repeat, so submission is described with the e-Services portal first and the call centre to confirm others. The Form 18 condition was only partly readable in my copy of the PDF, so it is marked "where applicable". Other entity types (institutions, trusts and so on) are not modelled. No issuance or acknowledgement step is documented for the TIN, so none is shown.
- Modelling limits: the planner allows one fee fact per service, so the birth search-case Rs. 250 and the NIC Rs. 120 postal charge are in wording and qualifications, not separate fee cards. A prerequisite cannot leave an optional branch option, so each route carries its own submit or receive step.

## 4. Feasible configurations (of 96) and policy
Before demo acceptance 4 each; after 64 each. Not feasible: the map (parallel coverage unknown). Phases are feasible for all three. The live trained policy (checkpoint copy; original file hash unchanged) scored all 64 candidates with 525 features per decision, and decisions record `content_state: demo_accepted`. Experienced profiles mostly received overview + concise + inline + phases, novices mostly guided + detailed + disclosure ON (`docs/C4-MAIN-SERVICES-LIVE.json`, 20 draws each). Feedback: first rating updates once, replay is identical, second rating 409, manual and guest views do not train. These official graphs and their 64 configurations were not part of the earlier synthetic study.

## 5. Presentation
White page and steps, thin grey rules, pale-gray fact cards, orange only for selection and optional support. The repeated "Local research demo wording" banner is removed from the card; the header keeps the agency and one compact "Prototype guidance · see Sources" line, and Sources states the AI-assisted, owner-accepted, unreviewed status. Conditional documents show their circumstance beside each document. Routes are placed after every verified prerequisite of any of their steps, so the birth submission no longer appears before "Complete the application".
